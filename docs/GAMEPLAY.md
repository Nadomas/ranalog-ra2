# Gameplay — ra2-analog

Базовый цикл: **Design → Configure → Test Room → Battle → Results**.

Критично: переходы **Design ↔ Configure ↔ Test** — максимально быстрые и желательно бесшовные, без долгих загрузок.

---

## 1. Design

Игрок создаёт робота:

- границы / форма корпуса;
- материалы;
- конструкция;
- размещение компонентов;
- соединения между компонентами;
- двигатели, колёса, оружие, приводы, батареи и др.;
- учёт массы, мощности, конструктивных ограничений и физики.

Цель фазы: рабочая физическая машина, а не «скин с хитпоинтами».

---

## 2. Configure

Каждый компонент предоставляет набор **actions**.

### Примеры действий

| Компонент | Действия |
|-----------|----------|
| Ротор | вращение вперёд, назад, остановка/фиксация, торможение |
| Поршень | выдвинуть, задвинуть, остановить |
| Колесо | вперёд, назад, возможно направление |
| Оружие | активация, деактивация |
| Другие | собственные действия |

Каждое действие может быть назначено на клавишу / кнопку / элемент управления.

### Группы

Компоненты объединяются в **группы**.

Группа может иметь **composite actions**.

Пример — 4 колеса в группе:

| Ввод | Поведение |
|------|-----------|
| W | все вперёд |
| S | все назад |
| A | левые назад + правые вперёд |
| D | левые вперёд + правые назад |

Игрок не только собирает робота — он **проектирует систему управления**.

---

## 3. Test Room

Мгновенный тест текущей конструкции.

Назначение:

- ошибки конструкции;
- ошибки управления;
- нехватка мощности;
- проблемы геометрии;
- неожиданное поведение физики.

Требование UX: **Design ↔ Configure ↔ Test** без традиционных долгих загрузок.

---

## 4. Battle

Бои **физические**.

Перспективный фокус — **PvP**.

Возможные форматы (не зафиксированы):

- 1v1;
- несколько роботов;
- турниры;
- elimination;
- timed battles;
- командные режимы;
- другие.

---

## 5. Results

После боя — статистика. Потенциальные показатели:

- нанесённый / полученный урон;
- повреждённые / уничтоженные компоненты;
- время активности;
- эффективность оружия;
- количество попаданий;
- энергия / мощность;
- мобильность;
- причина поражения;
- другие метрики по мере необходимости.
